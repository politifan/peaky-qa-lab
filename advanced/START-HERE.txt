QA advanced — редакция 3, 26.10.2026

Рабочая папка ZIP называется lab, в репозитории это advanced. Здесь requirements.txt, subject и seatlab.
Python 3.12, PowerShell:
py -3.12 -m venv .venv
.venv/Scripts/python.exe -m pip install -r requirements.txt
.venv/Scripts/python.exe -m playwright install chromium
Linux/macOS: python3.12 -m venv .venv, затем .venv/bin/python. Далее python означает этот путь.

Прочитайте subject/examples/boundary.py, затем напишите свой test_* в subject/submissions/m01-l01-p1.py.
python subject/check_public.py m01-l01-p1
python subject/check_sensitivity.py m01-l01-p1 --variant quantity
Второй запуск применяет тот же файл к good и дефекту. Проверяются непустой набор, min_tests, отсутствие skip/error и assertion failure на bad. Тривиальный assert True не подтверждает чувствительность. JUnit и source SHA256 сохраняются в новом subject/reports/sensitivity-*.json.
Для типа id выбирайте schema, точного повтора duplicate, нового процесса volatile, чужого чтения tenant_leak. Профиль должен соответствовать риску теста. Все варианты и маршрут Locust — в OPEN-MUTATIONS.txt.

Теория разделена небольшими блоками. Основная практика — .py, браузер или нагрузочный опыт на настоящем стенде; JSON-задача тренирует отдельный алгоритм. Один good-прогон не доказывает силу оракула.
Финал: один выбранный законченный QA-проект. Четыре области — варианты выбора. Сохраните свой код, команды, hash, good/bad результаты, изменённое условие, повтор из новой распаковки и ограничения. Самостоятельный повтор не называют проверкой другим человеком. Короткий отчёт TXT/Markdown достаточен. External Grader не подключён.
