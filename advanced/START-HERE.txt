Peaky Minds. Продвинутый тестировщик SeatLab. Дополнение 26.10.2026

Начальные навыки: Python функции/списки/словари, pytest assert и fixtures, HTTP JSON и базовый SQL. Если они новые, сначала базовый курс 301883. Проектный результат — одна выбранная специализация; четыре полных проекта не обязательны.

Распакуйте архив в отдельную папку, перейдите в lab (requirements.txt и seatlab рядом). В Windows PowerShell:
py -3.12 -m venv .venv
.venv/Scripts/python.exe -m pip install -r requirements.txt
.venv/Scripts/python.exe -m playwright install chromium firefox
В Linux/macOS: python3.12 -m venv .venv, далее .venv/bin/python вместо python. Системные зависимости браузеров устанавливаются по сообщению Playwright/его официальной инструкции. Активация среды и изменение ExecutionPolicy не нужны.

Далее python — тот же полный путь venv. Публичный tests/test_smoke.py читает health: он не проверяет весь курс. Содержательные тесты пишут в tests/test_student.py. Подбор --profile относится к pytest fixture; SEATLAB_PROFILE — к отдельно запущенному серверу.

Сетевой сервис в первом терминале lab:
python -m seatlab.app
Браузер: http://127.0.0.1:8765
Ctrl+C — останов своего сервера. Для отдельного сетевого профиля задайте SEATLAB_PROFILE и SEATLAB_DB до нового запуска. Смена environment не меняет уже работающий процесс.

run_probe.py использует TestClient, он не подтверждает сеть. Браузерная fixture live_url сама поднимает отдельный HTTP-сервер на свободном loopback-порту. Файл базы новый для независимого теста; один и тот же файл используется только внутри сценария сохранности после рестарта. Не смешивайте эти два требования.

subject/check_public.py запускает вашу работу на исправной публичной версии. Он не исполняет полный скрытый авторский набор и не начисляет Stepik-баллы. Не надо искать невыданный author.zip или отправлять работу несуществующему проверяющему. Исходный .py, наблюдения, показанный профиль дефекта, восстановление и границы — ваша самостоятельная приёмка. При наличии преподавателя используйте оговорённый с ним канал.

В конце выберите один из contract-lab / browser-quality / qa-dashboard / load-investigation, сохраните свои входы и вывод, один реальный отказ и возврат. Другие проекты — дополнительные. Баллы за алгоритмы Stepik отдельно оценивают объявленный JSON; они не являются экзаменом браузера, нагрузки или проекта. Рабочий отчёт может быть TXT/Markdown/DOCX; к защите достаточно одного связного отчёта. DOCX редакции 2 — справочная копия, актуальные уточнения — Stepik и этот файл.
